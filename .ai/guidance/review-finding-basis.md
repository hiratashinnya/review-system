# Finding の到達経路・前提脅威（Issue #830）

この文書を reviewer finding の **2つの根拠欄の規範上の正本**とする。実害判定の正本は引き続き `.ai/skills/review-harm/SKILL.md` であり、本書で `harm` / `harm_detail` を変更しない。

## 記載契約（各 finding）

- `reachability_path`（実運用での到達経路）: 誰が、どの実行入口・入力・操作順で、どの権限・環境条件下で問題箇所に達し、どう観測可能な不具合へ至るかを1行で記す。根拠となる実コード、テスト、仕様、運用手順の参照先も書く。未確認の経路を実証済みと断定しない。
- `threat_assumption`（前提脅威）: うっかり誤操作、通常の不正入力、偶発故障、悪意ある操作など、想定する行為者・能力・信頼境界を1行で示す。悪意を前提とする場合は、攻撃者がその入口を操作できる根拠または確認が必要な境界を示す。悪意を常に対象外と断定しない。
- 根拠が得られない欄には **`根拠なし`** と明示する。片方だけ判明した場合も、もう片方に `根拠なし` を入れる。**根拠が書けなくても finding は省略しない。** 憶測を確証として書かない。
- どちらも単一行の非空スカラとし、空値・リスト・改行・NULを禁止する。根拠の有無によって reviewer の `harm` / `severity` / `scope` を自動変更せず、レビュー結果を棄却・非ブロッキング化しない。

## 互換性と保持

新規 reviewer は両欄を必ず記す。Karte 取り込みは既存レポート・既存台帳の欄欠落を読み込める（未導入を表す内部値 `""`）。**明示的に記した空欄は不正**とし拒否する。

台帳上の旧形式は `reachability_path:` / `threat_assumption:` の空行としても読み戻せる。再レビューで旧形式の欄が欠けていても、同一 finding に保存済みの根拠は消さない。新形式の `根拠なし` は明示申告なので最新値として保存する。

本Issueは reviewer 入力・取り込み・保存のみを変更する。triager の根拠評価・棄却候補化（Issue #832）、owner の処置決定、Karte の verdict / clean 判定は変更しない。
