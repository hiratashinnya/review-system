- 本書は試験ケースの仕様（前提・手順・期待結果・判定）である。
- 実コード化：形態に「自動」を含むケースの自動部分は、工程 2a（test_design）で test-writer が Red の実テストとして `tests/codex_worktree_exec/` に置く（一次記録は Issue #655 本文 Scope 1 のオーナー決定（2026-10-18）。test-writer の契約文言に対するオーナー承認の例外であることは ST-TD-655 §1。配置は `.ai/agents/creation-stage-contract.md:44`）。
- 判定時点：形態に「CI」を含むケースは、「差分＋CI」のような複合形態でも、すべての部分（差分・CI 結果・ローカル実行）を merge 前に PR の最終 head commit で判定し、結果を ST-TR に記録する。ST-TC-655-08-1 も、形態は「差分」だが merge 前に PR の最終 head commit で判定する（手順は同ケース）。ST-TC-655-13-1 のうち ST-TD-655-13 の 7 の判定も、merge 前に PR の最終 head commit で行う（同ケースの残りの部分は次の規則どおり）。それ以外で形態に「CI」を含まないケースのうち、「文書」「差分」「コマンド」の形態と「3a」と書いたケースは、merge 後の ST-TR で主文脈が手順どおりに実行・判定する。
- 共通 fixture（F0）：`tests/unit/codex_worktree_exec_support.make_repository` と同等の一時 git リポジトリ。`ordinary.py` を commit 済み。テストは実行中の Python（`python3`）だけを使い、別 runtime の導入を前提にしない。
- 別 tag の値：現行と異なる tag には `cpython-399` を使う。fixture の作成時に `sys.implementation.cache_tag != "cpython-399"` を assert する（成り立たなければ環境不備としてテストを失敗させる）。
