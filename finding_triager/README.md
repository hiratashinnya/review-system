# Independent finding triage

`adapter.prepare` verifies a signed review against caller-supplied trusted bindings and returns the role and full harm SSoT in a prompt. A trusted execution host must dispatch that prompt in a separate read-only context with no source/ledger write, merge, waiver or network posting permissions. `adapter.propose` verifies the original again and combines its findings with independent structured assessments and the versioned policy. It returns a proposal; it never changes the review or makes owner decisions.

The review transport is UTF-8 JSON, signed using HMAC-SHA256 over its exact bytes. The trusted caller supplies the signing key and all expected bindings independently; neither comes from the review. The input digest is the caller's trusted digest for the review inputs; the review's own digest is recorded separately in provenance. The caller controls key distribution, isolation and assessment transport. This library does not claim to enforce those external boundaries and must not be used with an untrusted execution host. Each assessment has `finding_id`, `harm`, `scope`, nonempty `evidence` strings for `ac`, `vd_cp`, `design`, `change`, and `facts` containing all policy boolean inputs except the three set by the adapter. Unknown relations must set `evidence_complete` or `ac_relation_verified` false; absence of a mention is not proof of irrelevance. The result is a candidate, never an authorization or a disposition.
