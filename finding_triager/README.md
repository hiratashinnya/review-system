# Independent finding triage

`prepare` verifies a signed review and four evidence categories against a separately supplied trusted digest, then supplies the role and full harm SSoT with the evidence. The trusted caller must independently select the evidence and its digest; the strings are data, not instructions. Missing categories and digest mismatches are rejected.

`propose` accepts only a capture authenticated with a distinct trusted host key, domain-separated with `finding-triage-capture/v1` and a NUL byte. The capture contains the independent assessments, producer, all review bindings, review SHA-256 and context SHA-256. It is signed by the trusted host after its read-only triager execution; the triager must never have access to the capture key. The caller must maintain trusted key distribution and authorize the host. Validation recomputes the entire proposal from the authenticated capture and signed review.

The standalone `codex_worktree_exec` role `finding-triager` checks a trusted binding, a separate reviewer worktree, the reviewed OID and unchanged sources. It uses the pinned `adviser` read-only profile after verifying its capabilities, and signs the child output after successful execution. The caller supplies `TRIAGER_REVIEW_KEY` and `TRIAGER_CAPTURE_KEY` as distinct hex-encoded keys; they are not forwarded to the child. The binding includes review bytes as a UTF-8 string, review_signature, expected bindings, context bytes as a UTF-8 string, context_digest and reviewer_worktree. These inputs and the reviewer workspace identity must come from the trusted caller. The host writes the capture, signature and validated artifact to its new output file. The API cannot prevent a trusted host from signing fabricated results. Proposals are candidates only and do not confer authority to change the review, ledger, scope, or disposition.

The existing CLI still requires `--prompt-file`; for this role its contents are not used. The host builds the prompt solely from verified review/context and the role and harm contracts. The output path must not already exist. Execution requires a linked worktree and an existing, distinct registered reviewer worktree.
