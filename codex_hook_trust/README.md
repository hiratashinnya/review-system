# `codex_hook_trust` — Codex フック信頼状態の確認

このツールは、プロジェクトの `.codex/hooks.json` に定義されたフックと Codex が返すフック登録・信頼状態を照合する。通常は linked worktree からメインのチェックアウトを特定し、そのパスを確認に使う。

確認は次の順で行う。

1. Git の worktree 情報からメインのチェックアウトを特定する。
2. `.codex/hooks.json` に定義されたハンドラー数を数える。
3. Codex app-server の `hooks/list` を呼び出す。
4. 対象プロジェクトのフック件数と各フックの信頼状態を照合する。
5. 件数不足または未信頼のフックがあれば警告し、終了コード `1` を返す。

問題が検出されなければ終了コード `0`、確認に必要な情報を得られなければ終了コード `2` を返す。SessionStart フックは終了コード `1` の警告を追加コンテキストに載せ、終了コード `2` は出力せず終了する。

## 既知の限界

`--separate-git-dir` で作成したリポジトリの linked worktree では、`git worktree list --porcelain` の先頭がチェックアウトではなく外部 Git ディレクトリを示すことがある。この構成では `core.worktree` も設定されず、ツールはメインのチェックアウトを特定できない。観測した構成では、候補に `.git` が見つからないため、渡されたパスへフォールバックする。

Git が見つからない、Git コマンドが非ゼロで終了する、タイムアウトする、または出力から有効なメインのチェックアウトを特定できない場合も、同じく渡されたパスへフォールバックする。フォールバック時はそのパスの `.codex/hooks.json` と `hooks/list` を照合するため、信頼記録がメイン側にあると件数不足などの誤警告（終了コード `1`）になる場合がある。確認先がメイン側の信頼記録キーと異なる可能性も警告に明記する。

## 意図的な設計

メインの特定に失敗したとき渡されたパスを使うのは意図的な設計である。別のチェックアウトを誤って採用せず、無音の正常判定へ倒さず、ファイルシステム探索などによる推測もしない。判定不能の終了コード `2` にすると SessionStart フックでは無出力になるため、誤警告を出す経路より弱くなる。このためフォールバック先で照合を続け、異常が観測された場合は警告する。

この限界は、リポジトリの通常構成のように `.git` がディレクトリとして存在する場合には発生しない。
