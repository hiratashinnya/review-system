# audit/ — リポジトリ運営の点検記録

リポジトリ運営そのものを対象にした**点検の記録**を置く。成果物（`review_system/`・`doc-system-v2/`）
ではなく、**どう作っているか**を定点観測した結果が入る。

## ここに置くもの / 置かないもの

| 置く | 置かない |
|---|---|
| Issue 全数調査のような**横断・定点の点検結果** | 個別 PR のレビュー結果（PR コメント・カルテに残す） |
| そのとき使った**一次データのスナップショット**（分類表・指標の出力） | 進行中の作業状態（`tmp/` 配下） |
| 点検時点での**観測事実と分析**（根拠つき） | 処置計画・実施予定（Issue で管理する） |

**`spec-inspector`（仕様・設計の点検）や `asset-auditor`（資産の重複/競合監査）とは別物**。
それらは「活動」の名前で、対象は特定の成果物。ここは「リポジトリ運営の定点観測の記録置き場」であり、
エージェントが自動で書き込む場所ではない。

## 命名規約

```
audit/<YYYY-MM-DD>-<slug>/
  README.md     点検結果の本体（この1ファイルを読めば結論と根拠が分かること）
  data/         そのとき取った一次データ（後から再集計できる形で残す）
```

- 日付は**点検を実施した日**（対象期間ではない）。
- 既存の記録は**書き換えない**。後から分かったことは新しい点検として足す
  （`.claude/rules/01-principles.md`「PR8「消さない」の適用範囲」区分1＝経緯は保全する）。
  ただし**事実誤認が判明した場合は本文を訂正し、訂正したことと実施者を本文内に明記する**（同区分2）。
